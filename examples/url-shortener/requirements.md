# 要件定義: URL 短縮サービス

最終更新: 2026-04-30
ステータス: 確定

## 1. 背景・目的
長い URL を短い識別子に変換し、リダイレクトする最小機能。SNS 投稿やメール本文での可読性を上げ、ペースト時の改行・崩壊を防ぐ。

## 2. スコープ

### 対象
- 任意の HTTP/HTTPS URL を 7 文字の英数字に短縮
- 短縮 URL アクセス時にオリジナル URL へ 301 リダイレクト
- 短縮履歴の閲覧 (作成日時降順、認証ユーザー本人分のみ)

### 対象外
- カスタム短縮 ID (例: `/promo`)
- アクセス解析 / クリック計測
- 期限切れ / 削除機能
- レート制限 (本番運用時に別 feature として追加)

## 3. ユーザーストーリー
- US-01: マーケ担当者として、長いキャンペーン URL を短縮したい。なぜなら SNS 投稿の文字数を節約したいから。
- US-02: 短縮 URL の閲覧者として、リンクをクリックしたら正しい URL に飛びたい。なぜなら遷移時間を最小化したいから。
- US-03: 作成者として、過去に作った短縮 URL を一覧で見たい。なぜなら同じ URL を再短縮するのを避けたいから。

## 4. 機能要件
### FR-01: URL 短縮
**説明**: ユーザーが入力した URL を 7 文字の短縮 ID に変換し、短縮 URL を返す

**受け入れ基準**:
- Given 認証済みユーザー, When 有効な URL を POST, Then 短縮 ID を含むレスポンスを 201 で返す
- Given 認証済みユーザー, When 同じ URL を再度 POST, Then 既存の短縮 ID を返却し新規作成しない
- Given 未認証ユーザー, When URL を POST, Then 401 を返す

### FR-02: 短縮 URL リダイレクト
**説明**: 短縮 ID にアクセスされたら、対応する元 URL に 301 リダイレクトする

**受け入れ基準**:
- Given 存在する短縮 ID, When GET /:id, Then 301 で元 URL にリダイレクト
- Given 存在しない短縮 ID, When GET /:id, Then 404 を返す

### FR-03: 履歴一覧
**説明**: 認証ユーザーが作成した短縮 URL を新しい順で返す

**受け入れ基準**:
- Given 認証済みユーザー, When GET /api/links, Then 自分が作成した短縮 URL の配列を返す
- Given 認証済みユーザーで履歴が空, When GET /api/links, Then 空配列を返す
- Given 未認証ユーザー, When GET /api/links, Then 401 を返す

## 5. 非機能要件
| カテゴリ | 要件 | 指標 |
|---------|------|------|
| 性能         | リダイレクト応答 | p99 < 50ms |
| 可用性       | 月間稼働率 | 99.9% |
| セキュリティ  | open redirect 対策 | リダイレクト前に URL スキームを検証 |
| 保守性       | 短縮 ID 衝突時のリトライ | 最大 3 回 |

## 6. 制約条件
- 既存の Express + PostgreSQL スタックを使用
- 既存の認証ミドルウェア (`requireAuth`) を再利用
- 短縮 ID は base62 (英数字混在)

## 7. 前提条件
- ユーザーテーブルとセッション機構は既に存在
- DB マイグレーションツール (Knex) が導入済み

## 8. オープンイシュー
- (確定済み) ID 衝突確率: 7 文字 base62 ≈ 3.5 兆通り。月 100 万件作成想定で十分な余裕あり
